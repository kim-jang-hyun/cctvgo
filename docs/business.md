## 1. 제품 한 줄 요약

**지금 설치된 CCTV를 공유기 설정 없이 밖에서 웹브라우저로 보게 해 주는 Windows 설치형 소프트웨어입니다.**

- 판매 페이지: https://cctvgo.app (한국어/영어)
- 상태: 개발 종료(2026-11-04). 지금은 판매(수익화) 준비 단계이고, 아직 판매한 고객은 없습니다.

## 2. 고객이 겪는 문제

- 가게, 사무실, 집에 CCTV(IP 카메라, NVR/DVR)는 이미 있습니다. 하지만 밖에서 보려면 포트포워딩, DDNS, 고정 IP 같은 설정이 필요합니다.
- 처음부터 외부 접속 기능이 없는 CCTV도 있습니다.
- 설치 기사가 처음에 설정해 줬더라도 통신사 변경, 공유기 교체, IP 변경 등으로 어느 날 밖에서 안 보이게 됩니다.
- 고객은 네트워크를 모릅니다. 새 CCTV를 사거나 월 구독형 클라우드 CCTV로 바꾸고 싶어 하지도 않습니다.

## 3. 해결 방식과 차별점

- 카메라와 같은 네트워크의 Windows PC에서 실행하면 `고객ID.cctvgo.app` 주소가 생깁니다. 이 주소로 PC나 휴대폰 브라우저에서 영상을 봅니다. 전용 앱이 필요 없습니다.
- **고객 설정 0:** 공유기 설정 없이 쓸 수 있고, 첫 실행 때 방화벽 확인 창에서 "예"를 한 번만 누르면 됩니다. 카메라 주소(RTSP)도 카메라 계정만 넣으면 자동으로 찾습니다.
- **기존 장비 그대로:** RTSP를 지원하는 IP 카메라나 NVR/DVR을 그대로 씁니다. H.265 카메라도 PC 브라우저에서 볼 수 있습니다(자동 변환).
- **중앙 서버가 없습니다:** 서버 기능은 모두 고객 PC에서 돕니다. 고객이 늘어도 운영비(도메인비만)와 서버 관리 부담이 늘지 않습니다. 운영자가 퇴근 후에만 시간을 낼 수 있어도 사업이 굴러가게 하는 핵심 구조입니다.
- **영상은 제작자 서버나 클라우드를 거치지 않습니다:** 영상은 고객 PC에서 시청자 브라우저로 바로 갑니다(WebRTC). 운영비도 늘지 않습니다.
  - 영상이 제작자 쪽이나 클라우드에 모이거나 저장되지 않습니다.
  - WebRTC는 전송 구간 암호화(DTLS-SRTP)가 필수라서 영상이 암호화된 채로 전달됩니다.
  - IP 카메라 해킹이나 영상 유출 소식으로 클라우드 CCTV를 꺼리는 고객에게 내세우기 좋은 특징입니다.
  - 설명할 때 주의할 점:
    - 로그인, 화면, 연결 정보 교환(시그널링)은 Cloudflare를 거칩니다(HTTPS). "아무것도 외부를 거치지 않는다"고 말하면 틀립니다.
    - 처음 비밀번호는 운영자가 만들어 보냅니다. 고객이 비밀번호를 바꾸게 안내해야 "제작자도 영상을 볼 수 없다"고 말할 수 있습니다.
    - CCTVGO는 카메라 자체의 보안(초기 비밀번호, 펌웨어)까지 지켜 주지는 않습니다.
  - 판매 페이지 반영(2026-11-09):
    - 기능 카드 제목: "영상은 중앙 서버·클라우드 없이"
    - 기능 카드 본문: "영상은 중앙 서버나 클라우드를 거치지 않고, CCTVGO가 설치된 PC에서 보고 계신 웹브라우저(PC·스마트폰)로 암호화되어 바로 전달됩니다. / 외부 어디에도 저장되지 않습니다." (`/` 자리에서 줄을 바꿈)
    - FAQ: "영상이 외부 서버에 저장되거나, 제작자가 볼 수 있나요?" → "아니요. 영상은 CCTVGO가 설치된 PC에서 보고 계신 웹브라우저(PC·스마트폰)로 암호화되어 바로 전달되며, 제작자 서버나 클라우드에 저장되지 않습니다. 처음 받은 비밀번호를 바꾸시면 제작자도 접속할 수 없습니다."
    - 추천 대상: "영상이 클라우드에 올라가는 것이 걱정되는 분"
- **실시간:** 지연이 거의 없습니다.
- 비교 대상(제 생각, 조사 필요): 제조사 전용 앱과 P2P 클라우드, 월 구독형 클라우드 CCTV, 포트포워딩·DDNS 설치 대행.

## 4. 대상 고객

- 1순위: 매장 CCTV를 집에서 보고 싶은 자영업자, 기존 CCTV를 그대로 쓰고 싶은 사람, CCTV를 밖에서 간편하게 보고 싶은 사람, 영상이 클라우드에 올라가는 것이 걱정되는 사람(판매 페이지 기준)
- 구형 CCTV 사용자(국내/해외)
- 상업 용도: 매장, 사무실, 건물, 부동산 임대 관리 등(사용 허락 범위에 포함)
- 필요 조건: Windows PC가 카메라와 같은 네트워크에 있고, 항상 켜져 있어야 합니다(NVR PC에 함께 설치하는 것을 권장).

## 5. 판매와 전달 흐름 (현재)

1. 고객이 cctvgo.app에서 이메일과 원하는 접속 주소(고객 ID)를 입력해 신청합니다. 신청은 formsubmit.co를 거쳐 운영자 이메일로 옵니다.
2. 운영자가 `make_package.bat`에 고객 ID를 넣어 패키지를 만듭니다. 이때 Cloudflare 터널, DNS, 고객별 비밀번호가 자동으로 만들어집니다.
3. 운영자가 패키지와 접속 정보(주소, 비밀번호)를 고객 이메일로 보냅니다. 판매 페이지에는 "신청 후 2일 이내"라고 적혀 있습니다.
4. 고객이 `cctvgo.bat`을 실행하고 브라우저로 접속해서 카메라를 추가합니다.

- 문의 채널: 이메일, 카카오톡 채널
- 홍보 후보 채널(예전 계획): 판매 페이지, 네이버 카페, 크몽

## 6. 가격과 수익 모델 (정해지지 않음)

- 현재: **무료 베타**(판매 페이지에 "무료로 시작하기", "지금 무료로 신청하세요"로 표시). "월 이용료 없이" 기능 카드와 추천 대상 항목은 2026-11-09에 뺐습니다.
- 예전 계획: 무료 배포로 사용자를 모은 뒤 유료화
- 판매 형태: 설치형 완제품, 기술 지원 없음(사용 허락 범위와 면책 조항은 `customer/라이선스 및 고지.txt`)
- 의논할 질문:
  - 한 번 구매로 할지, 연간 요금으로 할지, 카메라 대수별로 받을지
  - 무료 베타 사용자를 유료로 어떻게 넘길지
  - 유지보수 시간이 적은 상황에서 지원 범위를 어디까지 약속할지
  - 설치 대행 업체나 CCTV 설치 기사에게 공급(B2B)할지
  - 미니 PC(라즈베리파이 등)와 묶어 파는 방안

## 7. 제약 조건 (사업 설계의 전제)

- **1인 개발자이고 회사원입니다.** 유지보수와 고객 응대에 쓸 수 있는 시간이 적습니다. 그래서 자동화, 자가 진단, 문의가 생기지 않는 구조가 중요합니다.
- **운영비 원칙:** 운영비는 도메인비 하나만 씁니다. 영상 중계 서버(TURN)나 그 밖의 유료 서비스는 쓰지 않습니다. 고객 기록도 서버로 모으지 않고 고객 PC에만 남깁니다(문의 때 진단 파일로 받음).
- **설치형:** 판매한 뒤에 고객 PC의 코드를 한꺼번에 업데이트하기 어렵습니다. 자동 업데이트 기능은 cloudflared에만 있습니다.
- 사업 목표: 회사 밖에서 현금 흐름을 만드는 것.

## 8. 위험 요소

| 위험 | 내용 | 현재 대응 |
|---|---|---|
| Cloudflare 계정 하나에 의존 | 모든 고객의 접속 주소가 운영자의 Cloudflare 무료 계정과 터널을 씁니다. 계정에 문제가 생기면 모든 고객이 함께 외부 접속을 못 합니다. | 영상은 Cloudflare를 거치지 않게 바꿈(약관 위험 감소). 나중에 Cloudflare를 걷어낼 수 있게 시그널링을 분리해 둠. |
| 도메인과 사업 지속 | 도메인 해지나 사업 중단 시 외부 접속이 끊깁니다. | 고객 고지문에 명시(보상·환불 없음, 로컬 사용은 유지). |
| 일부 네트워크에서 외부 시청 불가 | 회사망, 일부 통신사, 이중 공유기 등에서는 직접 연결이 안 될 수 있습니다(TURN 없음). | 화면 안내와 진단 파일. UPnP 추가는 실패 기록을 보고 판단. |
| PC 상시 실행 필요 | PC가 꺼지면 볼 수 없습니다. | 절전 방지 기능, 판매 페이지 FAQ에 안내. |
| 카메라 호환성 | 실제로 시험한 카메라는 2종(H.264, H.265)뿐입니다. | ONVIF와 경로 후보 85개, `rtsp-paths.json`으로 보강 가능. |
| 지원 부담 | 문의가 늘면 혼자 감당하기 어렵습니다. | 진단 파일 받기, 고지문에 "기술 지원 없음" 명시. |
| 오픈소스 라이선스 | FFmpeg(LGPL v3)를 함께 배포하므로 같은 버전의 소스를 제공할 의무가 있습니다. 판매 조건의 역분석 금지가 오픈소스 부품까지 막으면 안 됩니다. | 고지문에 정확한 버전과 "요청 시 3년간 소스 제공" 문구, 오픈소스 부품 예외 문구를 넣음(2026-11-07). 쓰지 않던 ONVIF Device Manager(GPL v2) 설치 파일은 패키지에서 뺌. FFmpeg 소스와 빌드 스크립트는 `oss-sources/ffmpeg/`에 보관함(git에 함께 커밋). 남은 일: 정식 판매 전 전문가 검토(예: OLIS 무료 상담). |
| 영상 코덱 특허 | H.264·H.265는 특허 풀(H.264: Via LA, H.265: Access Advance·Via LA 등)의 대상입니다. 동봉한 FFmpeg에는 소프트웨어 H.264 인코더(OpenH264, `--enable-libopenh264`)와 H.264·H.265 디코더가 이미 들어 있습니다. CCTVGO는 변환에 하드웨어·Windows 내장 인코더만 쓰지만, 배포하는 실행 파일에 코덱이 들어 있다는 점은 같습니다. H.264 풀은 해마다 일정 수량(알려진 기준 10만 개)까지 로열티가 없고, H.265는 풀이 여러 개라 조건이 복잡합니다(정확한 조건은 확인 필요). | 소규모 판매에서는 실제 부담이 거의 없음. 판매량이 늘면 확인. 줄이는 방법 후보: 쓰지 않는 코덱을 뺀 최소 FFmpeg 빌드. |

## 9. 카메라 대수

- 코드에는 대수 제한이 없습니다. 화면은 2줄로 배치되고, 열 수는 카메라 수 ÷ 2를 올림한 값입니다. 실제 한계는 PC 성능과 업로드 속도에 따라 달라집니다(측정하지 않음).
- 판매 페이지 FAQ에 있던 "최대 4대"는 2026-11-07에 지웠습니다. 대수별 요금을 받으려면 그때 제한 기능을 새로 만들어야 합니다.

## 10. 앞으로의 기능 후보

문의나 수요가 생길 때 추가합니다. 지금은 안정성을 우선합니다.

- UPnP(외부 연결 성공률 높이기): 실패 기록이 근거로 쌓이면 추가
- 녹화
- 카메라 IP가 바뀌었을 때 "다시 찾기" 버튼, 또는 MAC 주소로 자동 추적
- NVR 다채널 한 번에 추가
- Cloudflare 제거(시그널링 대체)
