# 카메라 관리 화면 (UI로 카메라 추가/수정/삭제) 설계

작성일: 2026-10-29

## 목적

지금은 설치하는 분이 `cctv.txt`에 RTSP 주소를 직접 적어야 한다. 앞으로는 **첫 카메라부터 웹 UI로** 추가하고, 이후 수정과 삭제도 UI에서 하게 한다. 카메라 주소 찾기(RTSP Finder)는 이미 있지만 두 가지가 걸림돌이다.

1. 찾기 결과 IP 목록을 **눌러야 한다는 사실을 사용자가 모른다**.
2. 저장한 뒤에 "cctvgo.bat 창을 닫고 다시 실행하세요"라고 안내한다. 이렇게 재시작하면 **이미 나오던 영상이 모두 끊긴다**.

## 목표

- 설정 → **카메라 관리** 화면에서 등록된 카메라를 보고, 추가·수정·삭제할 수 있다.
- 찾기 결과의 각 IP 옆에 **[추가] 버튼**을 둔다.
- 추가·수정·삭제를 **재시작 없이** 바로 반영한다. 바뀐 카메라의 영상만 켜거나 끄고, 다시 켠다.
- 패키지에는 항상 **빈 `cctv.txt`**를 넣는다.
- 카메라가 0대일 때 cctvgo.bat 상태 화면이 "고장"처럼 보이지 않게 한다.

## 비목표 (이번 범위 아님)

- 카메라가 0대일 때 영상 화면에 따로 안내하는 것 (사용자가 설정 버튼을 눌러 찾아간다고 봄)
- 카메라 순서 바꾸기
- 카메라 교체 기능. 다른 기기로 바꿔 끼웠다면 삭제한 뒤 추가하고, 새 카메라는 목록 맨 뒤에 붙는다.
- NVR 전용 추가 화면(채널 목록 자동 조회). 이번에는 고려하지 않는다. 대신 "RTSP 주소 직접 입력"으로 채널 주소를 한 줄씩 등록할 수 있다. 수정과 삭제 대상은 IP가 아니라 줄 전체로 구별하므로, 같은 IP 줄이 여러 개여도 정확히 동작한다.
- ffmpeg 자체가 `logs\stream_N.log`에 찍는 주소(비밀번호 포함)를 가리는 것. 이번에는 배치 파일이 출력하는 줄만 가린다(사용자 결정).
- 이미 쌓인 옛 로그 정리(사용자 결정: 그대로 둠).
- 이미 열려 있는 다른 기기 영상 화면의 실시간 목록 갱신 (새로고침하면 반영)

## 절대 안 되는 것 (안티 목표)

- **어떤 조작도 다른 카메라 영상을 끊으면 안 된다.** 추가, 수정, 삭제, 찾기 모두 해당한다. 기능이 동작해도 다른 영상이 끊기면 실패다.
- 기존 인증 실패 예산(카메라당 실패 2회 → 30분 대기)을 완화하지 않는다.
- 비밀번호를 로그나 화면에 평문으로 남기지 않는다.
- 사용자가 직접 편집한 기존 `cctv.txt`(주석 포함)를 깨뜨리지 않는다.

## 현재 구조 (설계에 영향을 주는 사실)

- `cctvgo.bat`이 `start_ffmpeg.bat`(cctv.txt를 줄 순서대로 읽어 `run_single_stream.bat`을 카메라마다 `start /b`로 실행), cloudflared, `cctvgo-service.exe`(Node 서버)를 순서대로 띄운다.
- 시작할 때 `start_ffmpeg.bat`이 `hls` 폴더를 지운다. 카메라 N번째 줄은 `hls\streamN\streamN.m3u8`로 출력한다.
- `run_single_stream.bat`은 ffmpeg가 끝나면 5초 뒤 다시 실행하는 무한 루프다. 따라서 영상 하나를 끄려면 **루프를 돌리는 cmd 프로세스와 ffmpeg를 함께** 종료해야 한다.
- 영상 화면(`LiveCctv.vue`)은 `/api/get-channel-list`의 **이름 목록**만 받는다. 그리고 i번째 카메라의 주소를 `/hls/stream{i+1}/...`로 **스스로 계산**한다.
- 카메라 주소 찾기 화면은 `frontend/src/views/CameraFinder.vue`(`/finder`)다. 서버 API는 `backend/finder/routes.js`(scan / probe / cameras / save), 파일 처리는 `backend/finder/cctv-file.js`(주석 보존, `.bak` 백업, 임시 파일 후 rename)에 있다.
- 비밀번호 평문 노출: `start_ffmpeg.bat`이 `Launching Monitor "1: rtsp://아이디:비밀번호@..."`를 `logs\ffmpeg_master.log`에 남긴다. `run_single_stream.bat`도 `echo RTSP_URL: ...`를 `logs\stream_N.log`에 남긴다.
- cctvgo.bat 상태 화면은 시작 직후 한 번 확인한 뒤 60초 동안 다시 확인하지 않는다. 그런데 서비스는 시작하고 약 10초 뒤에 뜬다(2026-10-29 로그 기준). 그래서 처음 1분 동안 "CCTVGO Service 작동 중지"로 보인다. 또 FFmpeg 개수가 0이면 무조건 오류로 표시한다.

## 화면 설계 (사용자와 합의함)

### 설정 메뉴
- "카메라 주소 찾기" 메뉴를 **"카메라 관리"**로 바꾼다.

### 카메라 관리 (첫 화면)
- 등록된 카메라 목록을 보여 준다. 각 행에는 이름, IP, **[수정] [삭제]**가 있다.
- 목록 맨 아래에 **[+ 카메라 추가]** 버튼을 둔다.
- 카메라가 0대이면 빈 목록과 [+ 카메라 추가]만 보인다.

### 카메라 추가
- [+ 카메라 추가]를 누르면 화면이 넘어가면서 **네트워크 찾기가 바로 시작된다**. [다시 찾기] 버튼도 둔다.
- 결과의 각 IP 행 오른쪽에 **[추가]** 버튼을 둔다. 이미 등록된 IP는 버튼 대신 **"등록됨"**을 표시한다.
- 맨 아래에 두 가지 직접 입력을 둔다.
  - **IP 주소 직접 입력**: 지금처럼 IP만 입력하고 자동으로 찾는다.
  - **RTSP 주소 직접 입력**(사용자와 합의):
    - 주소 칸에는 `rtsp://192.168.0.5:554/Streaming/Channels/201`처럼 설명서의 주소를 붙여 넣는다.
    - 아이디/비밀번호 칸을 따로 둔다. 비밀번호는 그대로 입력하고 인코딩은 프로그램이 한다(`encodeCred`). 주소 안에 아이디/비밀번호가 이미 있고 칸이 비어 있으면 주소 안의 값을 쓴다.
    - 이름을 입력하고 [접속 테스트 후 추가]를 누른다. 기존 probe의 수동 경로 테스트를 써서, 접속에 성공했을 때만 저장하고 영상을 켠다. 실패하면 인증 실패 예산과 기존 실패 안내를 그대로 적용한다.
    - 사설 IP 제한, 주소 형식 검증, `@` 중복 거부 등 지금 save의 검증을 그대로 적용한다.
  - 두 직접 입력 모두 이미 등록된 IP를 막지 않는다. 다만 **완전히 같은 주소**(호스트, 포트, 경로가 모두 같음. 아이디/비밀번호는 비교하지 않음)가 이미 있으면 "이미 등록된 카메라입니다"로 거부한다. 서버에서 확인한다.
- [추가] 다음 순서: 아이디/비밀번호 입력 → 주소 찾기 → (여러 스트림이면 선택) + 이름 입력 → 완료.
- 완료하면 cctv.txt 맨 뒤에 추가하고, **그 카메라 영상만 새로 켠다**. 재시작 안내 문구는 없앤다.
- 기존 "저장 방식(새로 추가/기존 교체)" 선택은 없앤다.
- 실패 안내, 잠금 방지 문구, 주소 직접 입력과 접속 테스트, 진단 정보 복사는 지금 동작을 그대로 유지한다.

### 수정
- 해당 카메라의 IP는 고정한다. **이름, 아이디, 비밀번호** 칸을 보여 준다. 이름과 아이디는 지금 값을 미리 채우고, 비밀번호는 비워 둔다.
- **이름만 바꾼 경우**: 카메라에 접속하지 않고 이름만 저장한다. 영상은 끊지 않는다.
- **비밀번호 칸을 비워 두면 기존 비밀번호를 그대로 쓴다**(빌더 판단). 서버가 cctv.txt에서 기존 비밀번호를 꺼내 사용하고, 비밀번호는 브라우저로 보내지 않는다. 빈 비밀번호로 시도해 실패 예산을 허비하지 않기 위해서다.
- **다시 찾는 순서(빌더 판단)**: 먼저 **지금 쓰는 포트와 경로를 새 계정으로 한 번만** 확인한다. 이렇게 하면 인증 시도가 가장 적다. 그게 안 되면 일반 주소 찾기(ONVIF, 경로 후보)로 넘어간다. 스트림이 여러 개 나오면 추가할 때처럼 선택 화면을 보여 주고, 기존 경로와 같은 것을 미리 선택해 둔다.
- **아이디나 비밀번호를 바꾼 경우**: 그 IP로 주소를 다시 찾는다. 성공하면 같은 줄(같은 순서)에 저장하고 **그 카메라 영상만 다시 켠다**. 실패하면 cctv.txt와 영상을 모두 그대로 두고 기존 실패 안내를 보여 준다.

### 삭제
- "○○ 카메라를 삭제할까요?"라고 한 번 확인한다(빌더 판단으로 정함). 확인하면 cctv.txt에서 그 줄을 지우고 **그 카메라 영상만 끈다**.

## 서버 설계

### 시작할 때 영상을 켜는 주체를 서버로 옮김 (빌더 판단)
지금은 `start_ffmpeg.bat`(배치의 `for /f eol=#` 규칙)과 서버(`trim()` 후 `#` 판단, 이름 없는 줄 제외)가 카메라 줄을 **서로 다르게 셉니다**. 공백 뒤에 `#`가 있는 줄, BOM, 이름 없는 줄이 있으면 번호가 어긋납니다. 번호가 어긋나면 삭제나 수정이 **다른 카메라 영상을 끌 수 있습니다**. 그래서 해석 규칙을 하나로 합칩니다.

- 시작할 때 영상 켜기는 **서버(`cctvgo-service.exe`)가** 맡습니다. 서버는 `cctv-file.js`의 `parseCameras` 하나로 줄을 해석하고, 카메라마다 `run_single_stream.bat`을 실행합니다. 이때 BOM 제거를 추가합니다. `/api/get-channel-list`도 같은 파서를 씁니다. 이름이 없는 줄은 "카메라 N"으로 표시합니다.
- 서버는 시작할 때 영상을 켜기 전에, 남아 있을 수 있는 `run_single_stream`/`cctvgo-ffmpeg` 프로세스를 정리하고 `hls` 폴더를 비웁니다. 서비스만 따로 다시 켜지는 경우에도 중복 실행과 번호 어긋남이 생기지 않게 하기 위해서입니다.
- `start_ffmpeg.bat`은 더 이상 영상을 켜지 않습니다. `cctvgo.bat`에서 [1/3] 단계를 없애거나 정리만 하도록 바꿉니다. 서비스가 뜬 뒤 영상이 켜지므로, 첫 영상은 지금보다 몇 초 늦게 나올 수 있습니다.

### 영상 번호가 바뀌지 않게 하기 (핵심)
줄 순서로 `streamN`을 정하면 가운데 카메라를 삭제했을 때 뒤 카메라의 번호가 당겨집니다. 그러면 그 카메라들까지 다시 켜야 해서 영상이 끊깁니다. 그래서:

- 서버가 **카메라 줄 순서 → 스트림 번호** 대응표를 메모리에 둡니다. 시작할 때 서버가 직접 `1..N`으로 영상을 켜면서 대응표를 만듭니다.
- 추가하면 **지금까지 쓴 번호 중 가장 큰 번호 + 1**을 새로 배정한다. 비어 있는 번호를 다시 쓰지 않는다. 그래야 꺼진 영상의 남은 HLS 조각이 새 카메라로 잘못 보이지 않는다.
- 삭제하면 대응표에서 그 항목만 뺀다. 다른 카메라의 번호는 그대로 둔다.
- 다음에 cctvgo.bat을 재시작하면 `start_ffmpeg.bat`이 1..N으로 다시 번호를 매기고 서버도 다시 초기화한다. 이때는 원래 모두 다시 켜지므로 문제가 없다.
- `/api/get-channel-list`는 카메라마다 **이름과 영상 주소(`/hls/streamK/streamK.m3u8`)**를 함께 돌려준다. `LiveCctv.vue`는 주소를 직접 계산하지 않고 이 값을 쓴다. 옛 응답 형식과의 호환은 필요 없다(프런트와 서버가 함께 배포됨).

### 영상 하나 켜기 / 끄기
- **켜기**: `start_ffmpeg.bat`과 같은 방식으로 `run_single_stream.bat "hls\streamK" "streamK.m3u8" 5`를 실행한다. 이때 `STREAM_URL` 환경변수를 넘기고, 로그는 `logs\stream_K.log`에 남긴다. 작업 폴더와 경로 기준은 배치와 같은 패키지 폴더(`BASE_DIR`)다. 출력 폴더가 없으면 만든다. cctvgo.bat 재시작이나 종료 때 `taskkill /T`로 함께 정리돼야 한다.
- **끄기**: 해당 `streamK`의 `run_single_stream.bat` cmd 루프와 그 ffmpeg를 함께 종료한다. 이 영상은 서비스가 띄웠을 수도 있고, 시작할 때 `start_ffmpeg.bat`이 띄웠을 수도 있다. 그래서 **프로세스 명령줄에 `streamK.m3u8`이 들어 있는지로 찾는다.** 이때 `stream1`이 `stream10`, `stream11`에 잘못 걸리지 않도록 경계를 정확히 비교해야 한다. 루프 cmd를 먼저 종료하고 ffmpeg를 종료해야 다시 살아나지 않는다.
- 다시 켜기(수정): 끄기 → 켜기. 같은 번호 K를 그대로 쓴다.
- 개발 환경(`node server.js`, BASE_DIR=backend)에서도 경로가 맞아야 한다. 배치 파일은 저장소 루트에 있고 hls는 `..\hls`에 있다.

### API (모두 기존 authMiddleware + 요청 횟수 제한 적용, 비밀번호 로그 금지)
- 목록: 등록된 카메라의 순번, 이름, IP, 아이디를 돌려준다. 비밀번호는 돌려주지 않는다.
- 추가: 지금의 save(append) 검증을 그대로 쓰고, 저장한 뒤 영상을 켠다.
- 수정: 두 가지 경우가 있다.
  - 이름만 바꾸는 경우: 이름만 고쳐 쓴다.
  - 새 주소로 바꾸는 경우: probe 성공 결과의 URL로 같은 줄을 교체한 뒤 그 영상을 다시 켠다.
  - 대상 카메라를 가리키는 값이 순번만 있으면, 그 사이에 다른 창에서 목록이 바뀌었을 때 엉뚱한 카메라를 고칠 수 있다. 같은 IP 줄이 여러 개일 수도 있다. 그래서 목록 API가 카메라마다 **줄 전체 내용의 해시**를 함께 주고, 수정·삭제 요청에 순번과 그 해시를 같이 보내 서버가 일치하는지 확인한다. 해시는 비밀번호가 드러나지 않는 방식(예: SHA-256)으로 만든다. 일치하지 않으면 "목록이 바뀌었습니다. 다시 열어 주세요"로 거부한다.
- 삭제: 수정과 같은 방식으로 대상을 확인한 뒤 줄을 지우고 영상을 끈다.
- cctv.txt 쓰기와 영상 켜기/끄기는 **한 번에 하나만** 실행한다(잠금). 파일 쓰기는 지금처럼 `.bak` 백업 → 임시 파일 → rename 방식을 유지한다.
- cctv.txt 저장에 실패하면 영상은 건드리지 않는다. 저장은 됐는데 영상 켜기/끄기가 실패하면 성공으로 처리한다. 다만 화면에 "저장은 되었지만 영상 적용에 실패했습니다. cctvgo.bat을 다시 실행하세요"라고 알린다.
- 기존 `/api/finder/cameras`와 `save`의 `replace` 모드는 새 API로 대체한다. 쓰는 곳이 없으면 정리한다.

## 배치 파일 / 패키지

- `backend/cctv.txt`: **완전히 빈 파일**로 커밋한다(사용자 결정). 지금 들어 있는 실제 카메라 2줄과 안내 주석을 모두 지운다. `make_package.bat`은 지금처럼 이 파일을 복사한다.
- 빈 cctv.txt에서도 `start_ffmpeg.bat`과 서버 목록 API가 오류 없이 0대로 동작해야 한다.
- 비밀번호 가리기(배치 줄만, 사용자 결정): `run_single_stream.bat`의 `echo RTSP_URL:` 줄에서 비밀번호를 가리거나 주소를 아예 빼고 출력한다. 서버가 영상을 켤 때 남기는 로그도 마찬가지다. `start_ffmpeg.bat`이 더 이상 영상을 켜지 않으면 그 Launching 줄은 사라진다. 남겨 둔다면 마찬가지로 가린다. ffmpeg 자체 출력은 이번 범위가 아니다.
- `cctvgo.bat` 상태 화면:
  - 카메라가 0대이고 FFmpeg도 0개일 때는 "등록된 카메라 없음 - 웹 화면 설정에서 추가"로 표시하고 오류로 보이지 않게 한다. 카메라 수는 cctv.txt에서 주석과 빈 줄을 뺀 줄 수로 센다. 카메라가 있는데 FFmpeg가 0개일 때는 지금처럼 오류로 표시한다.
  - 서비스가 시작된 뒤 일정 시간(예: 30초) 안에는 프로세스가 없어도 "시작 중..."으로 표시한다. 그 사이에는 몇 초 간격으로 다시 확인하고, 시간이 지나도 없으면 오류로 표시한다.
  - "30초마다 자동 갱신" 문구와 실제 대기 시간(60초)을 일치시킨다.

## 테스트

- 기존 백엔드 테스트(`backend/tests`, node:test 방식)를 그대로 따른다. 대응표(추가 / 삭제 / 번호 재사용 안 함), cctv-file의 줄 삭제·이름 변경, 대상 일치 확인, 잠금, 프로세스 명령줄 매칭(`stream1` ≠ `stream10`)을 단위 테스트한다. 실제 프로세스 실행과 종료는 주입 가능한 의존성으로 바꿔 테스트한다.
- 실기 확인(사람이 직접): 빈 cctv.txt로 cctvgo.bat 실행 → 상태 화면 확인 → UI로 첫 카메라 추가 → 재시작 없이 영상 확인. 두 번째 카메라를 추가할 때 첫 영상이 끊기지 않는지, 첫 카메라를 삭제하거나 수정할 때 다른 영상이 끊기지 않는지 확인한다.
