나는 CCTVGO라는 제품을 만들고 있어.

* 고객의 문제점 : 
내부망에 설치된 CCTV의 영상을 외부망에서 보지 못하는 경우가 있어.
원래부터 기능이 없었거나, 공유기를 교체한 후 외부접속 기능이 동작 하지 않는 경우가 있데.

나는 위의 문제를 해결하는 것을 목표로 삼았어.

외부 접속 기능은 cloudflare를 이용했어.
나는 도메인을 구입해서, cloudflare계정과 연결했어. 내 제품을 구매한 고객에게 사용할 subdomain을 알려달라고 할거야.
예를 들면 아래와 같아.
- 나의 도메인 : cctvgo.app
- 고객의 subdomain : customer
- 고객의 CCTVGO 접속 주소 : customer.cctvgo.app

위의 경우에 고객은 어디서든 웹브라우져로 customer.cctvgo.app에 접속하면 cctv 영상을 볼수 있는거지.

개발은 아래와 같이 했어.
고객의 PC 한대에 내 제품이 항상 실행되고 있어야해.
이게 내 제품은 문제점이라고 생각하는데, 내 고객들은 대부분 nvr을 동작시키는 pc를 가지고 있을 것 같아.
이 pc에 내 제품을 설치할 생각이야.
이럴 경우 기존 nvr에 악영향을 끼칠까?

내 제품은 아래와 같이 구성되어 있어.
ffmpeg을 이용해서 cctv의 영상을 rtsp로 수신후, hls로 변환했어. ffmpeg은 별도의 프로세스로 동작해.
web server를 개발해서 hls의 영상을 web page에 뿌려줘. node.js와 vue.js를 이용했어. hls재생은 hls.js를 이용했어.
cloudflared.exe를 이용해서 외부에서 내 web server에 접속할 수 있게 했어.

카메라를 2대 구입하여, 집에서 테스트는 했어. 몇몇 문제점이 있지만 기본기능은 동작하는 것을 확인했어.
개발에 너무 오래 걸릴것 같아서, 에이징 테스트 후 제품을 판매할거야.

제품 웹페이지를 만들고 판매해 나가면서 제품 개선 및 기능 추가를 할 거야.

내 제품은 설치할 때, 고객이 cctv.txt에 카메라의 rtsp주소를 입력하고,  .bat파일을 실행만 하면 설치가 되.
하지만 여기서 문제가 있어.

고객이 rtsp주소를 알아내기가 어려울 것 같아.
카메라의 주소를 알아내기도 어렵고, rtsp 주소를 알아내기도 어렵고, rtsp 주소를 알아도 카메라마다 rtsp 설정이 활성화 되어 있어야해.

이 단계에서 고객이 내 제품의 구매를 꺼려할 것 같아.

현재 문제점이 발견되어서 어떻게 해야할지 고민이야.
